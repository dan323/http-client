# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- Docs: `docs/features.md` is the user reference again (with a table of contents); implementation and security detail (class names, atomic-write mechanics, residual races, history layout, Public Suffix List update procedure) moved to the new `docs/design-notes.md`, same section names. Docs only; no behaviour change.
- Desktop: the **Forget responses** button is now **Reset chain** (the name the IntelliJ plugin uses) and the buttons under the request list are compact so the label fits.
- Desktop: the request list shows the HTTP method in the editor's method colour and bold.

### Fixed
- Desktop: the environment dropdown (and the recent files menu) opens directly under its button instead of far from it.

## [0.5.0] - 2026-11-08

The first release with the release workflow: the CLI zip and tar and the IntelliJ plugin zip are attached to the GitHub release. Desktop installers are built and attached on a best-effort basis. `0.5.0-rc1` was a pre-release used to test that workflow, the Windows installer and the plugin.

### Added
- IntelliJ plugin: its own icon for `.http` files (light and dark variants) and for the plugin listing, instead of a generic server icon.
- Desktop installers: the bundled runtime now includes `java.net.http` (without it the installed app could not send requests), and `./gradlew :desktop:checkRuntimeModules` (run in CI) fails when the app needs a JDK module the runtime lacks.
- Distribution (G9, T24): `.github/workflows/release.yml` runs on a tag `v*` (or manually for an existing tag), checks the tag against the project version, builds the CLI distribution (`./gradlew :cli:distZip` / `distTar`, `httpc-<version>.zip|tar`), the IntelliJ plugin zip and, best effort, the desktop installers (DMG on macOS, MSI on Windows, DEB on Linux), and attaches them to the GitHub release. Nothing is published to other channels (Homebrew, Scoop, winget, JetBrains Marketplace are listed as follow-ups in `docs/getting-started.md`).
- `docs/getting-started.md` (how to install each piece from the release assets; usage stays in `docs/features.md`) and `examples/smoke-test.http` with `examples/http-client.env.json`, linked from the README.

### Changed
- Cookie domain checks use the Public Suffix List (G8): a `Set-Cookie` `Domain` attribute that is a public suffix (`com`, `co.uk`, `github.io`, wildcard and exception rules included) is rejected unless it equals the request host, replacing the single-label check and the short built-in two-label list. The list ships as a resource in `core` (`public_suffix_list.txt`, version recorded on its first line; update procedure in `docs/features.md`), so `core` still has no third-party dependencies.
- Desktop installer version is derived from the project version (`0.5.0-rc1` -> `1.5.1`, `0.5.0` -> `1.5.99`) instead of the constant `1.0.0`, so a newer installer upgrades an older one.

### Fixed
- HTTP/2 pseudo-headers (`:status`) are no longer listed among the response headers in any front end, report or saved response; the status was already shown separately.

## [0.4.0] - 2026-11-07

### Added
- Differences from the JetBrains HTTP Client (G6): `docs/jetbrains-compatibility.md` lists, per area, only what is partial, not supported or deliberately different (with what happens instead), the deliberate deviations and what is not planned. Docs only; no behaviour change.
- `--fail-on-http-error` (G2): the CLI exits 1 when a selected request gets a response with status >= 400, also if its assertions pass; the failure is printed to stderr (even with `--quiet`) and recorded in the JSON report (optional `httpError` field) and the JUnit report (`failure` of type `HttpStatusFailure`, next to the `AssertionFailure` one when assertions failed too; `failures` still counts testcases). Prerequisites run only for chaining are not judged. Default behaviour is unchanged. `RunReport.from(..., failOnHttpError)` and `RunOutcome.Success.httpError` in `core`.
- Desktop persistence (T14, F11): `SettingsStore` port and `DesktopSettings` in `core`; `JsonSettingsStore` and `ConfigDirLocator` in `adapters` (per-OS user config folder, atomic owner-only `settings.json`, corrupt/newer files ignored and backed up as `settings.json.corrupt`, `.corrupt-1`, ... (newest 5 kept) before the next save; a transient read error never replaces the file; owner-only config folder). The desktop app restores the last file, its environment and the window (clamped to the current screens), saves changes in the background (debounced, flushed on close) and has a **Recent files** menu (10 entries; missing files are hidden but kept, environments capped at 50). Saves are serialised and `close` waits (2 s) for the one in flight; fullscreen is stored as maximized; the Windows minimized position is ignored. See `docs/features.md`.
- Saved responses (T26, F21): `>> path` (never overwrites; an existing name gets a numeric suffix, `out-1.json`), `>>! path` (overwrites) and `<> path` are parsed after the request instead of producing a warning (`RequestTemplate.saveResponse` / `responseLinks`; one save per request, empty path is a parse error; the lexer highlights the marker and the path). New `ResponseSaver` port in `core` with `LocalResponseSaver` in `adapters`: paths (with `{{variables}}`) are confined like `< path` reads, written atomically and owner-only, byte for byte; a rejected save fails only the save (`RunOutcome.Success.saveError`/`savedTo`), never the request, and happens after the assertions, also when they failed. The CLI prints `Saved response: PATH` on stderr and exits 1 when a save failed. `<>` links are kept in the history index only (the `.http` file is never edited): `HistoryStore.recordLinked` / `latestLinked` (backwards compatible defaults, `FileHistoryStore` stores an optional per-response key), `ResponseLinks`, `ResponseLinkRecorder` port, opt-in `SessionFactory(history = ...)` (wired in the CLI and the plugin). Review follow-ups: the newest record of every `<>` key is never pruned by other requests' runs (the 50-run limit still applies to the rest); the desktop app and the plugin show `Saved to PATH` and save/link errors (`OutcomeDisplay.Response.savedLabel/saveError/linkError/notices` in `view-model`) and the desktop app keeps `<>` links like the CLI; `>> text` as the last body line gives a warning when the path looks like prose; Windows-invalid names (`CON`, `NUL`, `file:stream`, trailing dots, ...) are refused on every platform; the printed saved path hides substituted values; `>>` of a prerequisite request fires (documented); the saver re-verifies the final real path after writing. Second review round: `>>!` is one rename inside the verified folder and `>>` hard-links the finished temp file (no empty reservation, no clobber); the folder's real path is re-verified right before publishing and a swapped folder makes the save fail without touching anything outside (residual race documented); paths with leading/trailing whitespace are refused instead of trimmed; the CLI never lets a report/`--output` replace a saved response and sends history warnings to its error stream; a `>>` path referencing another request makes it a prerequisite; cancellation inside a save/link is rethrown and runtime link failures become `linkError`; run ids carry a per-millisecond sequence (old ids stay readable) so `latestLinked` and pruning follow the recorded order, and only readable records protect a link key from pruning; `HistoryStore.recordLinked` / `latestLinked` no longer have defaults. See `docs/features.md`.
- Variable analysis (T13): `VariableAnalysis` in `core` (pure, IO-free) for editor intelligence. `VariableAnalysis.analyze(text, environmentNames)` returns diagnostics with stable codes, severities and exact ranges (UTF-16 offset, length, 0-based line and column) for undefined variables, `{{name.response...}}` to an unknown, later or own request, malformed response references, invalid dynamic variables, cyclic file variables, unterminated or invalid `{{`, duplicate request names and file variables used before their definition; `knownVariablesAt(offset)` (file, environment, response prefixes, dynamic templates); and find-usages (`findUsages`, `findVariableUsages`, `findRequestUsages`, `occurrenceAt`). Messages carry names only, never values. It shares the reference pattern and lookup order with `VariableResolver`, and a consistency test runs `samples/` and compares with run time. Not wired into the front ends yet. See `docs/features.md`. A file that does not parse is still analysed (each rejected line is a `parse-error`, once per `###` block, and left out), so editor features survive a half-typed request; `self-reference` and `request-not-run-yet` are warnings because they work in a session where the request already ran.

### Changed
- Wording (G6): the project no longer claims to be "compatible with" the JetBrains `.http` format; README, AGENTS.md, `docs/features.md`, the plugin description and the desktop package description now say it implements a practical subset of it, with additional testing and execution features.
- CLI `--output` is byte-exact (G3): it writes the raw response bytes as received instead of decoding them with the response charset and re-encoding as UTF-8, so images, PDFs and archives can be downloaded. Behaviour change: for a text response in a non-UTF-8 charset the file now holds the original bytes (e.g. ISO-8859-1), not a UTF-8 transcoding. New `OutputWriter` port in `core` (bytes), implemented by `AtomicReportWriter` (still atomic, owner-only, same path rules; a gzip/br response is saved still compressed, as received); `run(...)` of the CLI takes it as an extra parameter before the report writer.
- Default total timeout (G1): a request without `# @timeout` now fails after 60 s (headers and body) instead of waiting forever. `RequestTimeouts` in `core` (shared duration parser), `RequestRunner(defaultTimeoutMillis)`, `SessionFactory.create(defaultTimeoutMillis)`; configurable with the CLI `--timeout DURATION` or, for the CLI, desktop and plugin, with `-Dhttpclient.timeout` / `HTTPC_TIMEOUT` (`DefaultTimeout` in `adapters`). A bad configured value is reported, not replaced by the default. Use a long `# @timeout` for slow endpoints.
- `GRAPHQL`, `WEBSOCKET` and `GRPC` request lines are now a parse error naming the line (`Line 3: GRPC requests are not supported (only HTTP methods are sent)`) instead of being accepted and sent as plain HTTP requests (gap G4). Such a file does not run; `VariableAnalysis` reports it as a `parse-error` and keeps analysing the other blocks.
- Bounded XPath evaluation (G7): `ResponseExtractor` runs XPath on at most 4 daemon threads counted by a semaphore (`BoundedEvaluator`; idle threads exit after 30 s), so timed-out evaluations, which cannot be interrupted, can no longer accumulate; while all slots are busy a new XPath evaluation fails fast and finds nothing.
- `JdkHttpExecutor` follows redirects through the core `RedirectFollower` instead of the JDK client (G5). Behaviour changes for direct users: the hop limit is 10 (was the JDK's 5); exceeding it now throws `IllegalStateException("Too many redirects (more than 10)")` instead of the JDK's `IOException` (`ConnectException`), so callers catching only `IOException` must also handle it (nothing in this repository did); with `@no-cookie-jar` a same-origin hop now keeps the explicit credential headers (the JDK dropped them), as with the jar; the JDK's refusal to follow an https to http redirect no longer applies. The default client is `Redirect.NEVER`, an injected client with another policy gets a derived client per proxy. `RedirectFollower` is now public and also usable without the cookie jar (then neither read nor written). `@no-redirect`, the shared `@timeout` deadline and the summed duration are unchanged. New `RedirectCredentialsTest`; `JdkRedirectHeaderTest` now passes on JDK 21.0.2. Only `Cookie`, `Authorization` and `Proxy-Authorization` are stripped across origins; other custom headers (e.g. `X-API-Key`) are still forwarded, and 307/308 re-send the body to the new origin.

### Security
- Redirect credentials on every JDK (G5): an explicit `Cookie`, `Authorization` or `Proxy-Authorization` header is dropped when a redirect leaves the origin (scheme, host, port) and kept on same-origin hops, identically on every JDK and with `@no-cookie-jar`, instead of depending on the JDK version's forwarding.

## [0.3.0] - 2026-11-06

### Added
- History store (T11): `HistoryStore` port in `core` (`HistoryRun`, `StoredResponse`) and `FileHistoryStore` in `adapters` (`.http-history/` next to the `.http` file, injectable root, newest 50 runs kept, bodies cut at 5 MB with a marker, owner-only files on POSIX, atomic writes, one folder per run so concurrent writers cannot corrupt it, corrupt entries skipped). Not wired into the front ends yet. `.http-history/` added to `.gitignore`; stored responses are raw and may contain secrets. See `docs/features.md`.
- CLI (T10): `--quiet` (no per-request stdout; failed assertions and errors still on stderr), `--output FILE` (response body of the single selected request, through `ReportWriter`/`AtomicReportWriter`, owner-only, same path rules as reports; several selected requests are a usage error), `--var NAME=VALUE` (repeatable, overrides file and environment variables, values scrubbed from failure messages) and a summary line `N requests, P passed, F failed in Xs` on stderr. Exit code 3 now also covers an unwritable output file.
- Auth shortcut (T7, F3): `Authorization: Basic user password` and `Basic user:password` are Base64-encoded (UTF-8) at send time, after variable resolution; an already-encoded single token and other schemes are unchanged. The encoded value, the plain credentials and the password are scrubbed from failure messages. `Digest` and OAuth helpers are not implemented.
- Cookie jar (T3): `CookieJar` in `core`, owned per `RequestSession`; `Set-Cookie` responses are replayed as `Cookie` on later matching requests of the same session, and `# @no-cookie-jar [true|false]` (`RequestOptions.useCookieJar`) opts a request out of both sending and storing. Pure Kotlin, so it behaves the same through every `JdkHttpExecutor` derived client. The session follows redirects hop by hop when the jar is used (limit 10, honors `@no-redirect`, cookies stored and `Cookie` recomputed per hop, credentials dropped cross-origin), so `Set-Cookie` on a 302 works. Lenient `Expires` parsing, overbroad/IP `Domain` rejection, Secure-from-http rejection, Max-Age hardening, cookie count/size caps.
- `RunReport` (T9): pure report model in `core` built from `RunOutcome`s (per-request status, duration, assertions, error; totals; overall pass/fail), `JUnitXmlReport` in `core` and `JsonRunReport` (export and parse) in `adapters`. The CLI gained `--report-json FILE` and `--report-junit FILE`; console output is unchanged. Reports: one JUnit `failure` per failed request, unique `N. name` testcase names, passing prerequisites omitted (JSON: `prerequisite` flag), JSON `version` field, atomic writes, option validation, and exit code 3 when a report cannot be written (T9 review fixes).
- Dynamic variables v2 (T6): `{{$random.integer(a, b)}}`, `$random.float`, `$random.alphabetic/alphanumeric/hexadecimal(n)`, `$random.email`, `$random.uuid`, `{{$randomInt from to}}`, offsets on `$timestamp` / `$isoTimestamp` (`1 d`, `-2 h`; units `ms s m h d w M y`) and `{{$env.NAME}}` / `{{$processEnv NAME}}` via the new `EnvironmentVariables` port (`SystemEnvironmentVariables` adapter, wired in cli, desktop and plugin). `$env` is opt-in: no variable is readable until allowed by name, with `--allow-env NAME[,NAME]` in the CLI and `-Dhttpclient.allowEnv=` / `HTTPC_ALLOW_ENV` in the desktop app and plugin; others fail with an error naming the variable and how to allow it. Randomness, clock and environment are injectable through `DynamicVariables`. Malformed arguments fail with `Invalid dynamic variable`; unknown ones stay `Undefined variable`. `$uuid` and `$random.*` default to `SecureRandom` (a seeded `Random` can be injected); `$random.float` never prints scientific notation; `random.integer`/`randomInt` handle the full Long range; a malformed dynamic variable in an `# @assert` only invalidates that assertion. Dynamic references may contain spaces only for `$timestamp`, `$isoTimestamp`, `$randomInt`, `$uuid`, `$random.*` and `$processEnv`; `$` must be followed by a letter and references never span lines, so `{{$ x}}`/`{{$x := 1}}` text is untouched. `RequestRunner.resolveText` replaces the public `dynamic` property. `RequestRunner` gained an optional `DynamicVariables`. Example in `samples/dynamic.http`.
- Assertions (T5): `# @assert <expr> <op> [expected]` directives (`RequestTemplate.assertions`), `AssertionEvaluator` in `core`, results on `RunOutcome.Success.assertions`; the CLI prints PASS/FAIL per assertion and exits 1 when one fails. Example in `samples/assertions.http`. Unknown expression prefixes are invalid, numbers compare exactly (BigDecimal), `{{variables}}` are substituted, quoting for expressions with spaces and for empty/literal expected values, `matches` has a 2 s guard and dot-matches-all, a missing value fails every operator but `!exists`, `--request` asserts only the selected request, and the CLI summary counts assertions not run for failed requests. `RequestSession.runAll` gained an `assertFor` parameter and `RunOutcome.Failure.assertionsNotRun`.
- `ResponseExtractor` in `core` (T4): status, header, JSONPath, XPath (`body./x`, `body.xpath:`) and regex (`body.regex:`) lookups on a response, used by `{{name.response...}}` chaining and reusable by assertions. XPath and regex use the JDK only; DOCTYPE is rejected.
- Per-request executor options: `# @timeout`, `# @no-redirect` and `# @proxy host:port` settings are resolved into `HttpRequest.options` (`RequestOptions`) and honoured by `JdkHttpExecutor` (T2). Values are validated when the request is resolved (`Invalid @timeout`/`@proxy`/`@no-redirect`): positive whole timeouts with case-insensitive units and overflow checks, `@no-redirect [true|false]`, http-only proxies via the new `ProxyAddress` type (default port 80, no credentials). The timeout bounds the whole exchange (headers and body; see Fixed). `JdkHttpExecutor` caches derived clients, inherits the injected client's configuration and is `AutoCloseable`.
- Parser: `@var = value` file variables (override environment values, may reference other variables) and `# @setting [value]` directives, exposed as `RequestTemplate.fileVariables` / `settings` and `HttpFile.variables` (T1).

### Security
- Redaction and extraction hardening (R11): `RunOutcome.Failure.message` no longer contains substituted variable values (URL, header, body, assertion and chained-response values, raw or URL-encoded; replaced by `{{name}}`, values under 3 characters kept), so tokens cannot reach CLI stderr, JUnit or JSON reports through exception texts such as `URI.create` errors. XPath uses a hardened `XPathFactory` (secure processing, no external access) and is bounded to 2 s. `HttpResponse.bodyAsString()` honours the Content-Type charset (UTF-8 fallback); repeated headers are reachable with `headers.Name[i]` / `headers.Name[*]` (`headers.Name` still returns the first). `RequestRunner.resolve`/`resolveText` and `VariableResolver.resolve` gained an optional `onSubstitute` callback.
- File-read confinement (R5, deliberate deviation from JetBrains): `< path` / `<@ path` bodies can only be read from the `.http` file's folder, after `..` normalisation and symlink resolution; `../..`, absolute paths elsewhere and escaping symlinks fail the request with an error naming the path and how to allow it (no contents leaked). New `FileAccessPolicy` in `adapters` with extra allowed roots: CLI `--allow-file-root DIR` (repeatable), `-Dhttpclient.allowFileRoots=` / `HTTPC_ALLOW_FILE_ROOTS` (platform path separator) for the desktop app and plugin (use the env var in the IDE). Allowed roots are validated: empty, relative (property/env var), invalid and filesystem-root entries are rejected, `~` is expanded, the home directory only warns; dangling symlinks are judged by their target and the file is opened with `NOFOLLOW_LINKS` and re-verified.

### Fixed
- Desktop fixes (R10): the run guard is atomic; while a request runs, editing, saving, opening and creating files are refused (outcomes can no longer mix into another file); a run saves one snapshot of the text and a save error stops the run and stays visible; a failed environment refresh no longer keeps the previous file's environments; a stale selection reports "No request is selected"; response models (parsed JSON, decoded body) are built off the UI thread and cached per outcome; the request list is parsed when the text changes, not on every recomposition. New **Forget responses** button (drops the remembered chain).
- IntelliJ plugin fixes (R9): new IDE-independent `ClientState` (tested headless) with a run guard (a second trigger while one runs shows a balloon instead of racing on the shared session and report); sessions are bounded (16 files, least recently used evicted), dropped when the file's text changes, and dropped when the file is deleted or moved (VFS listener); report and environment-choice listeners are unregistered with their parent `Disposable`; the gutter icon saves documents first and finds its line in O(1); the service is registered by annotation only; new **Reset chain** button in the tool window.
- One composition root and shared run logic (R7): `SessionFactory` in `adapters` assembles executor, runner, dynamic variables, confined file reader, extractor and `RequestSession`, owns the `JdkHttpExecutor` and closes it (CLI per run, desktop on window close, plugin on project dispose); no front end wires these by hand any more. New `RunController` in `view-model` holds "request at the caret", "run with dependencies" and the session-per-(file, environment, variables) cache (stale revisions evicted, `resetChain`), with `RunTarget`/`RunResult`. **Desktop now keeps a session per file and environment, so a login request runs once and later Sends reuse it** (Send on a chained request no longer lists the reused prerequisites). `OutcomeDisplay` (`RunOutcome.display()`) maps outcomes to status class, header text and pretty-or-raw body in `view-model`; desktop and plugin only choose colours. File-access configuration errors, environment errors and interrupt handling behave as before; the desktop app now also reports a stale request index.
- Session robustness (R3): `RequestSession.runAll` rethrows `InterruptedException` (restoring the interrupt flag) instead of reporting it as a failure and sending the remaining requests; the session is safe for concurrent use (runs are serialised, `hasResponse` is lock-free); an invalid assertion (bad regex, non-numeric `<`, unknown operator) keeps its reason when a `{{variable}}` is used, with the resolved values left out. Refactors: redirect handling moved to `RedirectFollower`, option parsing to `RequestOptionsParser`, merged duplicated catch blocks, `VariableResolver.resolve` uses a lazily created shared `DynamicVariables.DEFAULT` instead of building a `SecureRandom` per call. Review fixes: with hidden values a bad-regex or missing-expected-value reason never echoes JDK/pattern/operator text (fixed `bad regex`); a caller queued on the session lock can be interrupted (`lockInterruptibly`, flag kept); `runAll` restores the interrupt flag itself when it catches a `CancellationException` caused by an `InterruptedException`; `RedirectFollower` takes an injectable clock.
- Environment resolution in one place (R6): new `EnvironmentLocator` port (adapter `UpwardEnvironmentLocator`: nearest enclosing folder with `http-client.env.json`) used by the CLI, desktop and plugin, which used to resolve different environments. Explicit `EnvironmentChoice` (`None` / `Named`): "(none)" no longer falls back to the first environment, an unknown or stale name is an error, and the plugin combo no longer resets the choice when set programmatically; combo and popup agree on "(none)". The CLI now honours `-Dhttpclient.allowEnv` / `HTTPC_ALLOW_ENV` merged with `--allow-env`. JSON `null` env values are skipped instead of becoming "null"; malformed env JSON raises `EnvironmentFileException` naming the file, line and column (never the file content, which may hold secrets). Running with no environment chosen does not read env files (the desktop app still reads them when opening or saving a request, and the plugin to populate its picker). The upward search stops after the first folder containing `.git` and never enters the home or temp directory (unless the `.http` file is in it); a folder with only `http-client.private.env.json` counts. The allowlist is the union of the system property, `HTTPC_ALLOW_ENV` and `--allow-env`. Plugin: **behaviour change**, the default environment is "(none)" (pick `dev` for the samples); the combo follows the active file, entries are matched by position, and an unreadable env file no longer shows the choice as "(missing)"; the session cache is invalidated when the env values change.
- Executor safety (R4): `# @timeout` now bounds the whole exchange, headers and body, and cancels the request (previously a server that sent headers and stalled hung forever); the default client has a 30 s connect timeout (no default total timeout). Interrupting the calling thread cancels the in-flight request, restores the interrupt flag and throws `CancellationException`. Documented that `Host`/`Content-Length`/`Connection`/`Expect`/`Upgrade` headers are dropped by the JDK client. Verified (tests) that `Authorization`, `Proxy-Authorization` and `Cookie` are not re-sent on cross-host redirects, so no change was needed there.
- R1 dependency scan and variable resolution: `withDependencies` follows `{{name.response...}}` through used file variables (transitively), `# @assert` expressions and setting values, and finds request names containing dots (split on the first `.response.`); a cyclic file variable fails with `Circular variable reference: a -> b -> a` instead of sending a literal `{{a}}`, and one resolve is bounded to 10,000 expansions / 100 levels; environment, response and dynamic values containing `{{` are no longer re-interpreted (only file variable values are expanded; so an environment value such as `"api": "{{host}}/v1"` is now sent literally, compose with file variables instead). A file variable's expansion is cached per resolve call unless it uses dynamic values, so the 10,000 limit counts distinct expansions, not uses; `@host = {{host}}/api` without an environment `host` reports `Undefined variable: host`, and cycle chains list only the cycle. `VariableResolver.withFileVariables` is replaced by a `fileVariables` parameter of `resolve`.
- Lexer and parser agreement (R2): `HttpLineLexer` no longer treats `@var = value` lines as the request URL (the gutter icon now lands on the real request line); lexer and parser share `HttpLineSyntax` (one method set and request-line classifier); lexer modes are the `HttpLineLexer.Mode` enum. An unknown method such as `GTE http://x` and a header line without `:` are `HttpParseException`s with a 1-based line number (a bare URL is still a GET). `> {% ... %}`, `> file` and `<> file` lines are no longer sent as body: they are skipped and reported in the new `HttpFile.warnings` (printed by the CLI on stderr). Only `< path` (with a space) is a file reference, so `<html>` bodies are plain text.
  Review follow-up: `GRAPHQL`, `WEBSOCKET` and `GRPC` are accepted methods and a one-edit typo gets a "did you mean" hint; a lone `GET` with no URL is a parse error; indented `?a=1` / `&b=2` lines extend the URL and indented lines without `:` fold into the previous header value; the lexer recognises handlers directly after headers; `> ` / `<> ` lines only count as handlers at the end of the block (earlier ones are body text); `%}` inside a quoted string does not end a handler script and a script that never closes warns; `<@ path` is a file body (variables in the file are not substituted, with a warning); the lexer ignores `\r` of CRLF line ends; the desktop request list shows the parse error.
- T6 review fixes: `$random.float` rejects equal endpoints (range is from-inclusive, to-exclusive); `EnvironmentVariables.isAllowed` denies by default; `$env` lookup is case-insensitive on Windows (allowlist stays exact); setting validation errors and assertion results no longer echo resolved `{{variables}}` (a failing assertion with substitutions reports `failed (expected value contains substitutions, not shown)`); the variable regex is linear on unclosed `{{$...` followed by long whitespace, never spans lines before `(`, and `{{$uuid }}` matches a `$uuid` override.
- IntelliJ plugin: stop bundling kotlinx-serialization in the plugin zip (the IDE provides it), avoiding a class conflict.
